# Content Guide

This portfolio should stay honest, specific, and student-appropriate. Keep the tone confident without overstating experience.

## Updating Project Cards

Project cards live in the `#proj` section of `index.html`.

When adding or editing a card:

- Use the real project name.
- Include a short, concrete description.
- Link only to public repositories or live demos.
- Keep tags focused on technologies actually used.
- Avoid adding projects that are not ready to show.

## Updating Links

Links appear in the nav, project cards, Good Plate section, contact rail, and footer. When changing a link:

- Use the full production URL.
- Keep `target="_blank"` and `rel="noopener"` for external links.
- Check the link manually after editing.

## Updating Skills

Skills live in the `#sk` section of `index.html`.

Only list skills and tools that Advik has actually used. If a tool was only tried once, keep it out until it is part of real work.

## Copy Style

- Write in first person where the section is personal.
- Prefer proof over hype.
- Keep claims measurable when possible.
- Do not inflate timelines, rankings, or project scope.
- Keep AI-assisted project wording honest about what was built, what tools helped, and what Advik contributed.

## Adding Symptom Match Studio Later

Do not add Symptom Match Studio until the project is ready to be included. When it is added, place it in the projects section with accurate links, tags, and status.
